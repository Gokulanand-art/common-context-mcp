The Problem

AI Agents Have Amnesia.

Every session starts from zero. Agents can't learn from each other, can't remember failures, and repeat the same mistakes. Switching agents means losing all context.

🧠

Session Amnesia

Agent A discovers the API uses JWT. Agent B starts fresh and tries OAuth. Same work, twice. Knowledge is lost between sessions.

→ Fixed: load_context() injects all prior knowledge
🔄

Repeated Failures

Agent tries Redis for sessions. Fails. Next agent tries Redis again. Fails again. Third agent tries Redis. Fails again.

→ Fixed: save_failure() + search_context() prevents repeats
🧩

Lost Context

Agent hits token limit mid-work. Everything learned is gone. Next agent starts blind. No checkpoint, no resume.

→ Fixed: Frequent checkpointing + interrupted session detection
⚡

Agent Conflicts

Two agents edit the same file simultaneously. Merge conflicts. Wasted time. No coordination mechanism exists.

→ Fixed: claim_area() + list_claims() prevents conflicts
📉

No Audit Trail

What was decided? Why? By whom? When? No record exists. Decisions are made in chat and forgotten.

→ Fixed: Every action recorded with timestamp + agent ID
🔀

Contradictory Decisions

Agent A decides "Use JWT". Agent B decides "Use sessions". No shared decision log. Chaos.

→ Fixed: broadcast() + save_context() for all decisions
The Solution

One JSON File. Shared Nervous System.

Every agent reads from and writes to a single append-only JSON file. What one agent learns, every agent inherits. What one agent fails at, no agent repeats.

FAQ

Got Questions?

How does the agent know to call load_context() first? +

The MCP server returns instructions in its initialize response. These instructions are automatically injected into the agent's system prompt by every MCP client. The agent is told: "FIRST ACTION: Call load_context() before ANY other work. MANDATORY."

What happens if the agent hits a session limit mid-work? +

Every save_context() call is a checkpoint. If the session is cut off, the last checkpoint is preserved in the JSON file. The next agent's load_context() detects the interrupted session and shows the checkpoint. The next agent can resume from where the previous left off.

Can data be deleted? +

No. There is no delete tool. The file is append-only. Context entries can be updated (overwritten), but sessions, failures, and broadcasts are never removed. This is a deliberate design choice to prevent knowledge loss.

Is it safe for multiple agents to use simultaneously? +

Yes. Writes use atomic file operations (write to temp, then rename). The claim_area tool prevents conflicts by letting agents claim files/areas before working on them. list_claims shows what other agents are working on.

Where is the data stored? +

In a single JSON file at ~/.shared-context.json. It's human-readable, git-friendly, and can be backed up with a simple copy command. No database, no cloud, no external service.

Does it work offline? +

100% offline. No network calls, no cloud services, no API keys. The MCP server runs locally via stdio transport. Your data never leaves your machine.

Which AI agents are supported? +

Any MCP-compatible agent: Claude Desktop, Claude Code, Cursor, OpenCode, Windsurf, Cline, Continue, and more. The post-install script auto-detects and configures all installed agents.
